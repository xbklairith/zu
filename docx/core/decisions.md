## Settled choices (not decision records)
- **Stack:** Go 1.24, CGO off; UI React 19 + `@xyflow/react` + ELK.js in a Worker, Vite-built, `go:embed`ed. Revisit Cytoscape if collapsed views exceed ~1,500 nodes.
- **Storage:** generated IRs and caches in git-ignored `.zu/`; the Policy file is committed.
- **Policy file:** one `zu.policy.yaml` at repo root, uml-viewer model (order, levels, foreign, edge-kind overrides, omit, omit-edges, proposals; demote and budget from feature 12, which the Policy hash leaves out); tests excluded by default; generated and vendored code excluded by glob. Importing `.go-arch-lint.yml` after v1.
- **Levels rule:** uml-viewer `:levels` on any Package Tree box or package (the longest ranked prefix wins; amended 2026-09-24, feature 06): listed inner first, higher-ranked → lower-ranked is a violation, same rank allowed, foreign/unranked not compared, a bundled edge is red if any pair inside it is, level 0 drawn at the bottom.
- **Baseline:** `zu.baseline.json` (sorted, committed) records known violations; `check` exits 1 only on new ones; `-update-baseline` only removes fixed ones (with no Baseline it creates one and lists what it accepts; a Baseline written under another Policy stops `check` with exit 3).
- **Cycles:** opt-in (`cycles: true`), between sibling Package Tree boxes; every arc in a cycle's strongly connected component is a violation. Noisy on repos with one big cycle, which is why it is opt-in.
- **Diff and the Policy:** both refs are scanned under head's Policy (ADR 0004 as amended); `diff` exits 1 on new violations when head's Policy has rules.
- **Diff base:** `git merge-base base head` by default; the Change View's Screens show one hop of unchanged neighbours, plain (18: the export's `near`; the tree draws only what changed). No merge-base (shallow clone) → exit 3 with the fix, never a fallback to the base tip.
- **Diff head:** `zu diff <base> [head]`, head defaults to the `HEAD` commit; `-worktree` opts in to uncommitted edits: the files the next commit would contain (tracked plus untracked, not ignored, read from disk); `-include-ignored` adds git-ignored files too. `zu scan` selects files the same way. Both refs are scanned fresh (no IR cache). A successful diff exits 0 whatever it finds; 1 stays reserved for new violations.
- **Diff scope:** both refs are scanned from the repository top level (`git rev-parse --show-toplevel`), whatever the current directory. In-tree file symlinks are resolved at a ref exactly as on disk, so a disk scan of a clean checkout and a ref scan of the same commit are byte-identical (submodule contents aside, since a commit holds only the gitlink; and files a smudge filter such as git-lfs or git-crypt rewrites on checkout, since a ref scan reads the raw blob). Not compared: `go.mod` changes (dependency versions, `go`/`toolchain` lines) and other languages' toolchain and dependency files; the docs and the summary footer say so.
- **Structural Summary (v1):** one row per changed package (+added ~modified −removed declarations), imports listed, call/embed changes as counts, Mermaid of changed packages + one hop (omitted above 30 nodes). Links (B6) are the HTML Export's (14): the Summary has none.
- **License:** Apache-2.0 (`LICENSE`). Public at v0.1 (scan + diff-to-CI working).
- **Audience:** the author first, then open-source users.
- **Mode B surface:** Structural Summary for CI leads; local UI diff view for depth. zu never calls a code-host API and ships no CI snippets — the JSON/Markdown output is documented.
- **Links (B6):** host detected from the `origin` remote (GitHub/GitLab), `-link-template` override. In a Change View whose sides are clean commits that a remote-tracking ref contains (14), each changed type or function links to its first changed line on the host's compare page, and each changed file to its diff there. On GitHub that is `#diff-<sha256(path)>` plus `R<head line>` or `L<base line>`; on GitLab, `?file_path=<path>#<sha1(path)>` or `#line_<sha1(path)[:9]>_A<head line>` / `_<base line>`. The lines come from one local `git diff -M -U3` of the two commits, a renamed file keyed by its new path; the anchors are computed offline. A declaration with no changed line in its span, or in a generated or deleted file, links to its file. What the change removed links to its source at the base commit, even when head is dirty. B6 is met once 14's by-hand check (a GitHub link past the compare's first four files, and a GitLab link, each scrolling to its line) has passed; until then it is 14's open risk. A diff link names the changed line: on a GitHub compare of at most 20 commits, on a pull or merge request with `-mr N`, or on any GitLab compare. Browsers may open it at the top (Chrome on GitHub). 'View at' always lands on the declaration. A GitHub compare of more than 20 commits hides its files behind a tab, so it gets no line links without `-mr` (14b).
- **Languages:** Go only; other files reported as unsupported, with counts.
- **Metrics overlay (A7):** CRAP colour in v1 as its own feature after interaction: cyclomatic complexity computed by zu, coverage from `go test -coverprofile`; missing data counts as red (uml-viewer). Mutation score after v1. Settled by feature 08: complexity is measured in the scan's one parse and carried beside the IR (`scan.Stats`), never in it, so the IR and its goldens do not change; the IR's `metrics?` stays unwritten and CRAP lives in the View. Input is an explicit `-coverprofile FILE`, only with `-html`. No profile draws nothing (A7's "degrade silently"); with a profile, a package none of whose function files it covers is red with "?". A Change View shows head's coverage only.
- **Test corpus:** zu, spf13/cobra, gohugoio/hugo, kubernetes/kubernetes, pinned to tags, fetched by script.
- **5-minute criterion:** the author, timed, on a public repo they have not read (hugo).
- **Product focus:** zu explains a project and a code change through interactive diagrams — the diagram is the explanation. No prose or doc-comment text in the UI.
- **Change reading order:** new violations first, then changed components bottom-up by dependency (infra → interface).
- **Build order:** scan → scan at a ref (feature 02) → diff to CI, no UI (feature 03) → HTML Export (static) → interaction → Policy file. `serve` after v1 core.
- **UI v1:** U1–U5 full (U2 from 15; from 05 to 14 it was reduced, full re-layout allowed); U6 = uml-viewer's declutter cycle (full → arrows → triangles → elements → classes → back to full, as in uml-viewer's `hierarchy.clj`; stage definitions in feature 05's Deviation 1; violations stay red). Externals drawn as ovals. Focus (N hops), collapse to depth N, external toggle (no stdlib toggle: the IR has no stdlib edges); view state in the URL hash. Views over 2,000 nodes or 500 drawn lines collapse depth automatically and say so. **Readable overview (11):** siblings are placed in rows by architecture rank (dependencies below dependents: Tarjan components, Eades–Lin–Smyth weighted cycle break, longest path; the Policy's Levels win in any sibling set that has one; more than 10 in a rank, or wider than 1,280 px, wrap into rows 6 px apart), from ranks alone, never from edges, so lines never move a box. Edges `auto` (default) / `on` / `off` in the hash (`l`); auto draws no line at rest over 40, except violations, changed imports and Affected imports, and a selected or hovered box draws its own (solid: it depends on; dotted: depends on it). The first view keeps labels at 11 px or more and pans (with a minimap) rather than shrink them. The page opens below single-child containers (external modules not counted), its breadcrumb starts there, and Esc never goes above it; siblings drop their shared path prefix, the full id in the title. `l=0` still means off. An axis labels the rows structurally ("uses ↓", "depends on nothing here" at the bottom); row names come only from Levels. The header counts the dependencies the cycle break set aside where it places the rows ("N dependencies run against the order", when there are any), with no colour. A Change View opens at the page root. **Grouping (12):** with two or more modules the page root draws the modules, and the module at the repository root opens in place above the others; up from inside it is the page root. Demoted packages (a directory segment on the built-in list: testdata, test, tests, \*testing, e2e, example, examples, sample-\*, hack, tools, scripts, third_party; a Policy `demote:` glob; or every declaration in a generated file; `!glob` keeps one; a changed package never) are counted into one Strip per sibling set, drawn in its bottom row and opened in place. At auto depth a view that draws more boxes than the Budget (15; Policy `budget:`) keeps that many and folds the rest into one Fold chip, "+N more", per sibling set, in the set's bottom row. It keeps changed and Policy-ordered boxes first, and at the page root the open root module's children that are not islands (never folded, but counted), then entry points (no project sibling imports it, it holds a package main, it uses a project sibling), then the most hand-written declarations (those not in generated files), then id; islands (no project sibling uses it, it uses none) fold first. A lone leftover stays drawn. A Strip reads "N tests & tools · used by K" (K: the boxes that use it, those in closed Fold chips included), a Fold chip "+N more", each naming the rest in its tooltip; a click opens either, and the header says how many boxes folded. A sibling set not placed by Levels is drawn in at most 7 rows (its groups' row included), adjacent ranks merged bottom-up into plain rows; the Panel names a merged box's own rank. The top row's axis label reads "entry points" when every box in it holds a package main; boxes carry path-role badges: `cmd` (a command's directory, or at least half its packages main), `internal`, `gen N%` (the share of declarations in generated files, from 50 %). IR packages gain the optional `main` (schema still "1"); `demote` and `budget` are not in the Policy hash. **Open in place (15):** a view's layout is the view as it opened plus a region for each container whose content the reader changed, each laid out on its own and set in its container's place. The view as it opened is the hash without box toggles (the root module's included) and without the selection; Fold chip and Strip toggles are kept, and the chip holding the selection is toggled in it, as N3 opens it. A region is a box the reader opened, or a container that now holds other children (a package closed at the declarations). A box keeps its place in its row; siblings right of an opened box move right by what it grew, and the rows below move down by what its row grew. Rows are not re-centred and may pass 1,280 px. Closing the box restores the prior layout exactly, and a hash lays out the same however it was reached (U3); a layout the page no longer wants never draws. Beside an opened box, the rows, Fold chips, Budget, declutter lift and counts are the view's as it opened. An opened box draws all its children, with no Budget, and their counts see every other opened box as closed. The weight filter (`w`) hides lines and never a box: ranks, ovals and counts read every bundle. A hop limit, a Fold chip or Strip toggle, a selection into or out of a closed Fold chip, or a change of depth, stage, focus, `w` or `e` lays the view out afresh and refits it. When an opened box is drawn past the canvas's edge, the camera pans just enough to show its top-left and as much of it as fits, never zooming or moving a box. Nothing is animated. **Screen (17):** a second lens beside the tree, toggled by `s` or the Screen button: the selection's Centre in the middle, what depends on it in the row above and what it depends on in the row below, placed without ELK. Each row wraps at 1,280 px into lines, the heaviest line nearest the Centre and each line laid out from its middle, so the first view, at the readable floor, shows the heaviest boxes. Its grain follows the Centre: imports for a package or external (Weight: files that import), calls and embeds for a type or function, a method drawn as its type (Weight: √(sites × declarations)). Boxes are sized against their row's heaviest: large from ½, medium from ⅕, small below; a row whose heaviest weighs 2 or less is medium, an external is always small, a type the Centre embeds is never small; labels are 12, 13 and 15 px. A row draws 24 boxes and a "+N more" chip; the chip or "every box" draws all (`m=1`). A box in both rows is drawn in each, marked ↻. A click re-centres. The hash keeps the Centre as `c` beside the tree's fields; entering, leaving or re-centring the Screen adds a browser history entry, so Back returns to the last Screen, and every other change still replaces the entry (05's Deviation 5). However the Screen is left, the tree comes back centred on its selection; its pan and zoom are not kept. Esc leaves the Screen after closing search; the tree's `d`, `+` and `-` do nothing on it. The header says what the rows and sizes are and, for a declaration, what the Screen leaves out: calls and embeds into it and out of it with declarations in packages not included, or in a Change View with unchanged declarations more than one call or embed from the change (the View's `offIn` and `offOut`, on types and functions only) and its package's Unresolved Calls. Search ranks a name's word starts (`RW`: ReadWriter) between name prefixes and id substrings. **Screen in a Change View (18):** a Change View opens on the tree, and `n` starts the Walk: each new violation's importer, then the changed packages bottom-up, each followed by the Centres of its changed declarations; `p` steps back, and a walk toolbar shows ◂ "3 of 10" ▸. Of a new cycle, whose every arc is flagged, the walk visits the importers of the imports the change added or reversed, or of each arc's first import when it made none on any. A Screen there reads the View with `near`: the unchanged declarations of head one call or embed from a drawn one (removed calls count, from base), their types, and every method of a type on the page, with the calls and embeds among them all; the tree never reads it. Each box carries its Change Status mark (a type with a changed method: has-change), each line its edges' status and sign (+ − ⇄ ±), and unchanged boxes are plain. A reversed import's far end is drawn in its row and as a Ghost in the other, small, dotted, uncapped. The Centre lists its changed members by id, signed + ~ − →, eight and then "+N more". The header adds where the Centre's package sits in the Affected Set (ADR 0009): changed, with how many packages import it, directly or not; N imports from a changed package; not in it; or removed. A line holding an import the Policy forbids is red on every Screen, as on the tree, and the walk's first steps are the new violations' importers. Leaving a near Centre selects its package and opens the full graph when the changed subgraph leaves that package out. On a Screen the changed-packages list re-centres, as search does, and the header keeps the change's link to the host. **Code panel (19):** a declaration's panel shows its file, coloured by `export.Syntax` (go/scanner, in Go: keywords, comments, literals, numbers; runs per line in UTF-16 units), drawn as text, never as markup, its line marked; of a file past 5,000 lines it draws the 5,000 around that line, and says which. Pointing at, or focusing, a call or embed row, or a Screen box or line, lights the lines it is written on (the View edge's `loc` and `more`; imports keep one location), the code scrolling on its own and a long file's drawn lines moving to the first; a note says where they are, listing places in other files. **Diff Code (20):** in a Change View, a declaration the change modified, removed or moved shows its own diff first: its whole text at Base, from its doc comment, against its text at head, numbered on both sides and coloured. Then come its file's hunks, coloured too. A removed declaration shows its text at Base. A Move that kept its text whole has none. Pointing at a call or embed the change removed lights the lines it was written on at Base, in the declaration diff, and the note names them ("Base line 20.", or "at base: path:line" outside it).
- **Firefox reload (16):** in Playwright's Firefox 155, reloading a zu page within about a second of its load can crash the tab: Firefox kills a page reloaded while a large `blob:` worker script (ELK's, 1.5 MB, inlined by Vite) is still loading. A page with no zu code and such a worker shows it; a 200-byte worker does not. Two page-side mitigations were tried and failed: terminating the worker on `pagehide`, and a `data:` URL worker. Loading the worker from a separate file would break the single-file page (ADR 0006). So the browser checks wait for the worker before a reload, and the page is unchanged. Whether release Firefox does too is untested: none was installed where 16 was measured.
- **Change View marks:** changed nodes solid, the Affected Set outlined; edges +/−, pair counts on bundles, cycle edges red; Moves dashed.
- **Output formats:** `diff`/`check` take `-format text|markdown|json`; markdown can be pasted as a PR comment; HTML via export. The summary includes the blast-radius count and says "no structural change" when only cosmetic edits were made.
- **Distribution:** GitHub Releases via goreleaser with checksums; `go install` after v0.1, once it can carry the UI (needs the module rename).
- **Serve (10):** `zu serve [dir] [-addr host:port] [-include …] [-link-template …] [-coverprofile …] [-poll interval] [-base ref]` serves the working tree's Project View on a loopback address only (default 127.0.0.1:7433, a free port when that is taken), answers only requests whose Host names this machine, and has no write endpoint; it writes nothing to disk. The page is the HTML Export's, fetching its View from `/view.json` under the export's CSP plus `connect-src 'self'`. Each page load rescans; `scan.Cache` re-parses only files whose content changed and assembles again only the packages whose files changed, that are new, or that import a path where a package appeared, went, or changed its name, functions or types (16). It assembles the whole tree when the modules change (a module's path or directory, or a require's path or line; a version alone changes nothing), or when two ids could meet: a package's id, or the path of a required module the tree does not hold, is another package's id plus "." and more, or such a path is a package's id (directory names may hold dots). The IR stays byte-identical to a cold scan's; `TestCorpusRescansMatchColdScans` checks it on a copy of a corpus tree. Session restore is the URL hash on the fixed port. No `-open`: git is the only process zu runs. **Watch (13):** every `-poll` (default 1 s; 0 off; at least 100 ms), zu serve stats (size, mtime, ctime, inode) what a rescan reads (non-test Go files, `go.mod`s, and the Policy even if git ignores it), every directory the scan does not prune, every `.gitignore`, and git's `HEAD`, `index`, `packed-refs` and the ref `HEAD` names. It lists the tree again only when a directory, a `.gitignore` or a git file changed. A burst of changes costs one rescan, and one rescan runs at a time. The watch's rescan trusts each file's stamp, as a page load does not (10 Deviation 3). It publishes the View over Server-Sent Events (`/events`: the generation and a notice; `/view.json?latest`) unless the rescan failed or, at the same commit, a file that parsed no longer does. In that case the page keeps its drawing and shows the notice. The page redraws in place, keeping the URL hash, pan and zoom, and a hidden page closes its stream. **Change View (14):** `-base ref` serves the Change View of the working tree against the merge-base of `ref` and HEAD, the View `zu diff ref -worktree -html` writes, at the repository's top. Each rescan resolves `ref` and the merge-base again, and it rescans the base only when the merge-base or the Policy's hash moved. `-include` does not apply. A push or fetch shows at the next save or reload. **Code (19):** without `-include` zu serve details every package while the scan, as the Policy draws it, holds at most 20,000 declarations (past that, packages only, said once on stderr) and inlines no source; the page reads a file from `/source?path=` (an `export.SourceFile`: text and colour), which answers only for files the last scan declares a package, type or function in, read through the scanned tree, and is 404 for anything else. With `-include` the page is `zu scan -html`'s, its View byte for byte. With `-base`, `/source` answers too, from the working tree.
